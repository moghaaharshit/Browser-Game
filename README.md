# NEON CITY DRIVE 🚗🏝️

A driving / on-foot game made with **Godot 4**. The whole world is **one procedurally
generated island, 8.6 × 8.6 km**, floating in the ocean. **18 towns** are scattered across
it — not on a grid, randomly placed on three jittered rings — each with its own landmark
and its own style, joined by 20 winding country roads. Nine **rivers** flow from the hills
down to the sea, there are lakes, and **166 drivable vehicles** stand parked in the streets
and on the open road — **eight different kinds**: sedan, sports, SUV, panel van, pickup,
jeep, monster truck and motorcycles (with a rider). On
foot you carry **ten Free-Fire style weapons** — rifles, SMGs, a shotgun, an LMG, two
scoped sniper rifles — plus **grenades**, **gloo walls** (three at a time) and **medkits**.
Right click always looks through a real **circular sight** (a red-dot ring on the rifles,
a full magnified scope on the two snipers), **TAB opens a GTA-5 style weapon wheel**, and
every house and shop has **random loot lying on its floor**: guns + ammo, body vests,
helmets, grenades, gloo walls and medkits.

**Everything is generated by code at runtime.** No imported models, no textures, no audio
files — the whole game is pure GDScript.

## ▶ How to run it

1. Install **Godot 4** (standard build, not .NET) — https://godotengine.org/download
   Tested on **Godot 4.7.2**; anything from 4.3 up should work.
2. Open Godot → **Import** → pick `project.godot` from this folder → **Import & Edit**.
3. Press **F5** (Run Project).

Or from a terminal:

```bash
godot --path /path/to/neon-city-drive
```

The first couple of seconds bake the island height field, place the 18 towns and build the
town you spawn in, then you are free to walk / drive.

## 🌐 Put it on GitHub Pages (playable link, no download)

The repo is ready to deploy itself: `.github/workflows/deploy.yml` downloads Godot
4.7.2 + the export templates, exports the **Web** build (`export_presets.cfg`) and
publishes it to GitHub Pages on every push to `main`.

```bash
# 1. create an empty repository on github.com, then in this folder:
./tools/deploy_github.sh https://github.com/<your-name>/<your-repo>.git
#    (or do it by hand)
#    git init -b main && git add . && git commit -m "Neon City Drive"
#    git remote add origin https://github.com/<your-name>/<your-repo>.git
#    git push -u origin main

# 2. on GitHub:  Settings → Pages → Build and deployment → Source: GitHub Actions
# 3. wait for the green tick in the Actions tab (~3 min), then open
#    https://<your-name>.github.io/<your-repo>/
```

**Already verified:** the exported build was loaded in a real Chromium (headless,
SwiftShader WebGL2) — the engine starts, the whole island bakes (`road corridor:
2874 grid vertices levelled`), the town renders, 0 JS errors, and a click grabs the
pointer. See `screenshots/64_web_build_in_browser.png`.

**No git at all?** The build is also sitting in `neon-city-drive-web.zip` next to
this folder — drag that onto <https://app.netlify.com/drop> (no account needed for
a temp link) or unzip it into any static host / itch.io HTML5 project. GitHub's own
web uploader refuses the 38 MB `index.wasm`, so for GitHub use the Actions route.

Notes:

* The web build uses the **Compatibility (OpenGL)** renderer and the
  **single threaded** template, so it runs on GitHub Pages without any special
  `Cross-Origin-Opener-Policy` headers (SharedArrayBuffer is not needed).
* First load pulls ~38 MB (WASM) — after that the browser caches it. The page works
  on phones: the viewport meta tag, `touch-action: none` and the landscape
  orientation are already set.
* To build the same thing locally: `./tools/build_web.sh` then
  `python3 tools/serve_web.py` and open http://localhost:8000 (it serves `.wasm`
  with the right MIME type; `file://` will not work).

## 📱 Phone controls (touch)

The game builds its own thumb controls — **no image files, no scene files**, every
button is drawn with `_draw()`. They switch themselves on when the device reports a
touch screen (`DisplayServer.is_touchscreen_available()`, or a mobile/web build) and
stay hidden on a desktop. **F9** forces them on or off, and `--touch` on the command
line does the same for testing.

```
   ┌───────────────────────── CAM ⬤ BAG ⬤ MAP ─────────────────────────────┐
   │                                                    minimap            │
   │                                                                       │
   │                        (drag anywhere on the right                     │
   │                         half of the screen to look)                    │
   │  ╭───────╮                                          ⬤ JUMP          │
   │  │ MOVE  │                             ⬤ CROUCH                     │
   │  │ stick │   ⬤ RELOAD   ⬤ CAR      ⬤ SPRINT      ╭────────╮         │
   │  ╰───────╯                                        │  FIRE  │         │
   └───────────────────────────────────────────────────╰────────╯─────────┘
```

* **Move stick (bottom left)** — analogue and *floating*: it appears wherever your
  thumb lands in the bottom-left corner and follows it, so you never have to look
  down. Push it half way and you walk at half speed.
* **FIRE (bottom right)** — press to shoot, and **keep dragging your thumb to aim**
  while the gun is firing, exactly like Free Fire's drag-fire: the drag turns the
  camera, so you can spray and track a target with one thumb. Air control, punch and
  the three hit combo work the same way.
* **SPRINT**, **JUMP**, **CROUCH** (toggle), **RELOAD**, **CAR** (get in / out).
* **BAG (top centre)** — opens the weapon wheel. It stays open until you tap a
  weapon (or tap outside to close), so you never have to hold anything.
* **CAM** cycles the camera, **MAP** opens the big map (pan and tap a destination
  with your finger — the map already works with touches because the engine emulates
  the mouse for it).
* While the controls are on, the HUD rearranges itself: the speedometer moves to the
  top-left, the ammo counter sits above the fire button and the item strip goes to
  the top-left, so nothing is under a thumb.
* **Driving**: the same stick becomes throttle / brake / steering (push up to go,
  down to brake, left/right to steer) and the right cluster turns into
  **BOOST**, **BRAKE** and **EXIT**.

Everything the buttons do goes through the normal input actions
(`Input.action_press("punch")`, `walker.touch_move = …`), so the keyboard code path
is still the only source of truth: a phone and a desktop play the same game.

## 🔫 Gunplay (Free-Fire style)

Ten weapons, all built out of boxes and cylinders at runtime — receiver, barrel,
hand guard, magazine, grip, stock, iron sights, rails, charging handle, ejection
port, trigger + guard, bipod where it belongs, and a real scope with a glowing
lens on the two bolt-action rifles.

| # | Gun | Class | Damage | RPM | Mag | Notes |
|---|---|---|---|---|---|---|
| 1 | **M500** | pistol | 62 | 150 | 6 | semi, huge headshot multiplier |
| 2 | **UMP** | SMG | 22 | 700 | 25 | full auto |
| 3 | **MP40** | SMG | 17 | 950 | 30 | fastest fire rate |
| 4 | **M1014** | shotgun | 13 × 10 pellets | 110 | 6 | 7.5° cone |
| 5 | **AK47** | rifle | 34 | 560 | 30 | 2.2× headshot |
| 6 | **M4A1** | rifle | 30 | 640 | 30 | low recoil |
| 7 | **SCAR** | rifle | 36 | 540 | 30 | hardest hitting rifle |
| 8 | **M60** | LMG | 38 | 480 | 100 | drum mag, bipod |
| 9 | **KAR98K** | sniper | 92 | 42 | 5 | scope, one-shot headshot |
| 10 | **AWM** | sniper | 118 | 38 | 5 | scope, 16° zoom |

* **Drag fire** — hold the left button and keep steering with the mouse; the gun
  keeps firing at its own RPM. A tap fires a single shot.
* **Aim down sights (right button) — on every single gun.** The camera goes
  first person and a **realistic circular sight** opens in the middle of the screen:
  * the two snipers (KAR98K, AWM) get the full **magnified scope** — black
    eyepiece, soft lens vignette, cool coating sheen, duplex posts, mil dots and
    a rangefinder ladder, 16–20° FOV;
  * every other gun gets a **red-dot / holo ring** — thin housing, glass tint,
    glowing centre dot — at a gentler 36–46° FOV.
  Both fade in smoothly and the cone tightens while you aim.
* **The aim never climbs on its own.** Firing kicks the arms and blooms the
  crosshair, but the muzzle stays exactly where the mouse put it — no auto
  rise, so you never have to drag the mouse back down.
* **Weapon wheel (hold TAB)** — GTA-5 style: the ten guns around the ring plus
  grenade, gloo wall and medkit. The mouse picks the slice, the hub shows the
  name and how much you carry, let go of TAB (or click) to equip it. Whatever
  you picked fires from the left mouse button.
* **Headshots are real hit boxes.** Every bot has separate head / chest / legs
  boxes, and a head hit always drops it (the shot multiplier is applied first).
* **Crosshair** grows with spread and recoil bloom, shrinks when you crouch or
  aim; white **hit markers** and a **HEADSHOT! / KILL** popup confirm hits.
* **Grenades (H)** — physics frag grenade, bounces, 2.6 s fuse, 8.5 m blast that
  hurts bots, sets off fuel drums and shoves the player.
* **Gloo walls (G)** — a translucent cover panel with a real collider that stops
  bullets. **Only three can stand at once: place a fourth and the oldest one
  disappears** (exactly like Free Fire). You carry five; **ten seconds after you
  place one the stock refills itself** (the HUD counts the seconds down next to
  the GLOO slots), and loot tops it up too.
* **What is in your hand is what you see.** The weapon wheel drives a real model
  in the right hand: the equipped gun (held in *both* hands — right fist on the
  grip, left hand on the hand guard), a grenade, the blue gloo canister or the
  red-cross medkit. The model is placed from the animated hand positions every
  frame, so the hands are always on it whatever the pose is doing.
* **Firing squares you up.** Stand facing one way, whip the mouse round and pull
  the trigger: the whole avatar snaps round to the side you shot at (and aiming
  down sights keeps the body on the sight line), instead of shooting out of the
  back of its head.
* **Jumping** throws the arms **forward** and up with the knees tucked; with a
  weapon in hand the two-hand grip is kept while you are in the air.
* **Loot (E)** — **every** house on the whole map is stocked (each of the four
  floor spots rolls 94 %, so a house is never empty), plus two behind the counter
  of every shop — a block can hold up to 30 pickups:
  guns (+ammo for that gun), body vests, helmets, grenades, gloo walls and
  medkits. They glow, bob and spin; walk up to one and the HUD says
  **[E] SCAR AMMO**.
* 6 practice bots spawn on the road near you; they take body damage, die to a
  headshot, fall over, and come back after six seconds.

## 🗺️ The island

* **One landmass.** A procedural height field (`scripts/island.gd`, 4300 m half-size,
  **18 m grid**, 479 × 479 samples = 229 000 vertices) with an irregular lobed
  coastline, bays, a mountain spine that peaks at **310 m**, beaches at sea level and
  the ocean plane running out to 13.7 km.
* **Detailed mountains.** The spine is built from a ridged noise plus a second,
  higher-frequency *crag* noise (broken rock faces) and a *gully* pass that cuts
  erosion channels into the flanks, so the peaks are craggy instead of one smooth
  cone. The terrain is painted per vertex: three grass tones blended by two noises,
  banded rock strata on every steep face, scree fields under the snow, and a snow
  line at ~254 m with a noisy edge that refuses to lie on the cliffs. Below the
  grass line the rivers get wet-mud banks.
* **Rivers.** Nine rivers are traced downhill from the hills to the coast, then cut into
  the height field as a wide graded valley (78 m half-width, 2.6 m deep bed) with their
  own water ribbon mesh that follows the slope — so you get creeks running *between*
  the hills, not only at sea level. The water is a **custom shader**: two scrolling
  sine fields drive the colour (deep teal → pale turquoise) and the roughness, so the
  surface genuinely flows and glitters in the sun. Where a river meets the land the
  vertices turn wet mud and sand, so every bank reads as a bank. Lakes fell out of the
  same noise.
* **Everything is solid.** Terrain (one `HeightMapShape3D`), every building wall,
  every tree trunk, palm, rock, bench, lamp post, parked prop car, bus, fuel drum,
  drivable car and bot has a collider, and a safety clamp lifts the player back on
  top if the capsule ever ends up under the island — you climb the mountains, you
  never walk through them.
* **The terrain is real collision**: a `HeightMapShape3D` built from the same baked grid,
  so the walker and the cars climb the hills exactly where the mesh says they should
  (verified: physics floor and analytic height agree to 0.01 m).
* **18 towns**, randomly placed on three rings (4 + 6 + 8), at least 1 000 m apart, on
  ground flatter than 30 % and at least 5 m above the sea. Each town is a 4–6 × 4–6 grid
  of 64 m blocks with 16 m streets, its own landmark in the middle, and its own mix of
  buildings (residential, glass towers, shops, school, police, hospital, club, parks,
  plazas, lots) depending on the town's kind — industrial, neon, rural or nature.
* **20 roads**: a minimum spanning tree over the 18 towns plus a few loops, drawn as
  asphalt ribbons (7.4 m half-width, gravel shoulder, dashed centre line, solid edge
  lines) sampled every 9 m, and flattened into the terrain as 30 m corridors, so the
  roads ride the hills instead of cutting through them.
* **No grass on the tarmac.** The road ribbons are re-sampled from the *baked* height
  field after the terrain mesh is built, so the asphalt and the ground agree to the
  centimetre — over a crest the terrain can no longer bulge up through the road.
* **Streaming.** A town is built when you come within 950 m and freed past 1 400 m, at a
  7 ms per frame budget. While a town is streamed *out* you still see a cheap silhouette
  of it (block pavements + 2–4 boxes per block), so the island reads as a city island from
  the air and from the far coast instead of a field of empty plates.
* **166 vehicles in eight kinds**, every one a full physics `PlayerCar` you can get into
  and drive: 7 parked in the streets of every town plus ~40 more spread along the country
  roads, spaced so they never overlap. Ten bright show-room colours rotate through them,
  so no car is a black blob, and each one is tilted to the slope it is parked on.
  * `sedan` — the everyday car · `sports` — low, wide, big wing
  * `suv` — tall 4x4 with roof rails · `van` — long panel van with rear doors
  * `pickup` — cab + open cargo bed · `jeep` — short, roll cage, snorkel, spare wheel
  * `monster` — 0.88 m tyres, raised chassis, roll cage, chrome stacks
  * `bike` — two wheels, frame, tank, forks, pipes **and a rider**

  They are not clones: every kind has its own length, width, wheel size, wheelbase,
  ride height **and its own handling numbers** (top speed, acceleration, steering rate,
  grip, brakes, boost). A monster truck is slow and steady, a bike is quick and nervous.
  The spawn mix depends on where you are: town streets are full of sedans and the odd
  bike, the open road gets pickups and 4x4s, and above ~115 m the mountain roads get
  jeeps and the occasional monster truck.
* **The ground is solid.** Every surface you can stand or drive on is real
  collision, and it is the *same* surface you can see:
  * the terrain is one `HeightMapShape3D`;
  * every town's asphalt plate has its own box collider (it is drawn 6 cm above
    the height field, which is exactly the sinking people saw before);
  * every country road ribbon has a trimesh collider built from the same points
    as the mesh it draws, sitting 10 cm above the road's own smoothed profile.
  So a car's tyres rest on the tarmac, the pavement and the dirt at **0.00 m**
  error in town and within a couple of centimetres of suspension travel on the
  mountain roads — measured over 24 drive-along runs of 100–330 m each.
* **Roads that are actually roads.** The height field used to give 50° mountain
  climbs and bulged up through the asphalt on every crest (measured: 24 % of the
  road width was buried, up to 20 m deep, which is what made a car look like it
  was driving into the ground). Now the road profile is smoothed and grade-capped
  at 12 %, and the terrain is cut and filled around it: inside the strip the
  ground is levelled 30 cm under the tarmac and it blends back into the hill over
  the next 15 m. No grass pokes through a road any more, and no invisible hill
  bump stops the car.
* **Step assist.** A kerb, a road edge or the lip of a town plate is a few
  centimetres high, and a `CharacterBody3D` stops dead against it. If the car is
  blocked where it is but free 34 cm higher, it climbs — so you can drive off the
  tarmac onto the verge, over a kerb and into a town without getting stuck.
* **Real gravity.** Gravity is Earth's **9.81 m/s²**, on foot and in a car. A car
  dropped from 20 m lands in 2.02 s (the textbook answer). The ground clamp and
  the suspension are what keep a car planted, not extra gravity.
  On foot: walk **2.6 m/s**, sprint **6.4 m/s**, jump at **4.6 m/s** — a 1.08 m
  high jump that keeps you in the air for 0.94 s, with limited air control.
* **Wheels that sit on the road.** The car probes the ground under every wheel each tick,
  pitches and rolls the shell to the slope, and *then* — after the body has its final
  pose — puts each tyre centre exactly one radius above the surface below it, solved in
  model space. Measured over 800 wheel samples on the mountain roads the worst tyre dip is
  **5 mm** (it was 19 cm before that second pass).
* **Suspension and animation.** The wheels spin at the true rolling speed for their own
  radius, the front wheels steer, a bike's fork turns and the bike leans hard into a
  corner, the body dives on the brakes, squats on the throttle, dips on landing and
  floats over crests. Tyres are built from 16 tread blocks, a sidewall, an alloy rim,
  5 lug nuts and a hub, so they read as tyres at two metres.
* **Detailed ground.** The terrain shader carries a procedural noise grain (triplanar
  projected, so it never stretches), and the whole island outside the towns is covered in
  streamed ground cover: pines, boulders and shrubs in 48 m tiles that appear within 180 m
  of you, three `MultiMesh`es per tile so a whole hillside is three draw calls. They are
  deterministic per tile, they never grow on a road or in a town, and they sink into the
  bank on a slope so nothing floats.

## 🏠 Buildings you can walk into

**Every** house lot in every town is now walk-in (not three of four), and the shop
floor at the bottom of every commercial tower is a real room too: a doorway with a
frame and an open glass door, glass shop windows with mullions, an awning, a neon
sign, and inside a counter, shelves, crates and a ceiling light.

Every house builds **rooms, not props**:

* an open front door, windows with frames, glass and sills on all four sides;
* ground floor with sofa, table, chairs, TV, bookshelf, kitchen counter, fridge, dining
  table and a ceiling light that switches on when you walk in;
* a **staircase up to the second floor** (bed, wardrobe, desk, nightstand) and a second
  staircase to the **roof** (water tank, AC unit, bench — and the whole town to look at);
* every floor piece is its own collider, both stair corridors stay clear, and the whole
  thing is batched into the same 3 draw calls per block as everything else;
* **random loot on the floors** — up to 4 pickups per house (ground floor and upper
  landing), plus two behind the counter of every shop. Guns (+ammo for that gun), body
  vests, helmets, grenades, gloo walls and medkits. Each one glows, turns slowly and
  bobs; stand on it and the HUD shows **[E] BODY VEST**, press **E** and it is yours.

Red/blue **explosive drums** stand in the towns: punch one or ram it with a car and it
blows up — fireball, dust ring, smoke, flying debris, and a chain reaction to every drum
within 7 m.

## 🧍 Avatar

A fully procedural humanoid built from boxes with plain `Node3D` joints — no skeleton
resource, no animation clips. Every pose is computed each frame: idle breathing and
head turns, walk and sprint cycles (legs and arms swinging in opposition, pelvis bob,
torso counter-rotation and lean), crouch, prone crawl, jump tuck, and a three-hit punch
combo. **The avatar faces −Z, the same direction it moves**, so limbs always swing on the
side you are travelling — the model, its face and its gait are all built from the same
forward axis.

* **Minimap (top-right, always on)** — a real 3D orthographic render 260 m across,

## ⚡ How it stays smooth

1. **Batched meshes.** Every block writes all of its boxes, windows, fences, trees and
   lamps into a single `ArrayMesh` with 3 surfaces (opaque, emissive neon, glossy glass).
   Vertex colours carry the colour data, so there are no textures at all.
2. **Town streaming** — nearest town first, block by block, with a per-frame time budget;
   blocks behind you are freed. Generation is deterministic, so a town looks identical
   when you come back.
3. **Far skylines** — one merged silhouette mesh per town (built once at boot) stands in
   while that town is streamed out, so distant towns still look built-up.
4. **One terrain mesh + one heightfield collider** for the whole island, plus one ocean
   plane and one river mesh.
5. **Physics interpolation on**, so cars, the walker and the camera are smooth between
   60 Hz ticks — no jitter at speed.
6. **Cheap collision**: box colliders per building, one `HeightMapShape3D` for the island.

## Known limitations

* The far-town silhouettes are boxes (no windows) — you only see them from far away.
* Ground cover (trees, boulders, shrubs) is decoration: it has no collider, so you can
  drive through a pine. The terrain, the buildings, the barrels and every vehicle are
  solid.
* A parked vehicle's wheels are placed once when it spawns; if the terrain under it were
  to change it would not re-settle (the terrain never changes).
* The road/terrain cut is applied to the 18 m height grid, so where two mountain roads
  join at a sharp angle the cut can still leave a small fold in the grass (measured: the
  worst remaining spot is 10 % of sample points and under 8 m, all of it off the tarmac
  and outside the driving corridor). It never reaches the asphalt — the drive-along tests
  cross those junctions at 100+ km/h without a bump.
* Rivers are cut at the terrain grid resolution (18 m), so their banks are a little
  blocky; they stop short of the towns instead of running through them.
* Traffic AI cars are currently **off** (the 166 drivable cars replace them); they can be
  switched back on in `main.gd`.
* Bots stand still and respawn — there is no enemy AI and no safe zone. The gunplay
  (weapons, sights, damage, headshots, gloo walls, grenades) and the loot are all there;
  turning the bots into a match is the next step.
* Loot respawns when a block is streamed back in — it is a sandbox, not a saved world.
* There is no audio yet (the project ships no sound files).
